# 安全与性能问题排查清单

> 用于代码筛查时的安全与性能隐患识别。按「严重 → 警告」分级，每个问题给出识别特征和修复建议。

## 一、安全类（🔴 严重）

### 1. 硬编码密钥 / 密码 / Token

- **识别**：代码中出现 `password = "..."`、`api_key = "..."`、`secret = "..."`、AWS/阿里云 AccessKey、JWT secret、数据库连接串等。
- **修复**：改用环境变量（`os.environ` / `process.env` / `System.getenv`）、密钥管理服务（KMS / Vault）、配置文件（加入 `.gitignore`）。
- **注意**：即使出现在注释或测试代码里，也要提示检查是否泄露真实密钥。

### 2. SQL 注入

- **识别**：拼接 SQL 字符串，如 `"SELECT * FROM users WHERE id = " + user_input`、f-string 拼 SQL、`Statement` 拼接。
- **修复**：使用参数化查询 / PreparedStatement / ORM 的查询构建器。

### 3. 命令注入 / 代码注入

- **识别**：`os.system()`、`subprocess` 拼接用户输入、`eval()` / `exec()`、`Runtime.exec()` 拼接。
- **修复**：避免 `eval`/`exec`；子进程用参数数组而非字符串拼接；对用户输入做白名单校验。

### 4. XSS（前端）

- **识别**：`innerHTML` 直接插入用户数据、`dangerouslySetInnerHTML`、未转义的模板渲染。
- **修复**：使用框架的安全绑定、对不可信内容做转义、配合 CSP。

### 5. 敏感信息日志泄露

- **识别**：日志打印密码、Token、身份证号、手机号等。
- **修复**：日志脱敏，禁止打印凭证。

### 6. 不安全的反序列化

- **识别**：Python `pickle.loads()` 处理不可信数据、Java `ObjectInputStream` 反序列化不可信输入。
- **修复**：避免反序列化不可信数据，改用 JSON/安全格式。

## 二、安全类（🟡 警告）

| 问题 | 识别特征 | 修复 |
|------|---------|------|
| 弱加密算法 | MD5/SHA1 用于密码、DES、硬编码 IV | 用 bcrypt/scrypt/argon2 存密码，AES-GCM 加密 |
| 明文传输 | http 明文接口、关闭 SSL 校验 | 强制 HTTPS，校验证书 |
| 路径遍历 | 拼接用户输入到文件路径 | 规范化路径、白名单校验 |
| 越权访问 | 接口未校验资源归属 | 服务端鉴权 + 资源归属校验 |
| 弱随机数 | `random`（非密码学）用于 token/验证码 | 用 `secrets` / `SecureRandom` |

## 三、性能类（🟡 警告）

| 问题 | 识别特征 | 修复 |
|------|---------|------|
| N+1 查询 | 循环内逐条查询数据库 | 批量查询 / JOIN / 预加载 |
| 循环内字符串拼接 | 循环里 `+=` 拼字符串（Python/Java） | 用 `join()` / `StringBuilder` |
| 无界循环 / 死循环风险 | `while True` 无退出条件、递归无终止 | 明确终止条件，加保护 |
| 重复计算 | 循环内重复调用昂贵函数 | 提取到循环外缓存 |
| 未释放资源 | 文件/连接未关闭 | `with` / try-with-resources / 连接池 |
| 过大的内存占用 | 一次性加载大文件到内存 | 流式/分块处理 |
| 低效集合操作 | 列表 `in` 判断（O(n)）在循环内 | 用 set/dict（O(1)） |
| 阻塞主线程（前端） | 同步大计算、同步请求阻塞 UI | Web Worker、异步化 |

## 四、排查原则

1. **安全 > 性能 > 风格**：优先报告安全问题，性能次之。
2. **置信度优先**：高置信度问题标「严重」，需结合业务判断的标「警告」。
3. **给出可执行的修复**：不只说"有问题"，要给出具体改法或代码示例。
4. **不误报**：区分"真的密钥"与"占位符/示例代码"（如 `password = "example"` 是演示而非泄露）。
